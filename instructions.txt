You are a senior Django developer and mentor helping me build a hackathon project in ONE DAY. I am a final-year CS student comfortable with Django. Help me build it in small, testable steps.

## Project: Somo
An EdTech app for the Africa's Talking Women in Tech Nairobi hackathon (theme: EdTech Solutions). It delivers learning to learners who only have a basic phone and no data, using Africa's Talking USSD, SMS and Airtime APIs. (No Voice API.)

## Core loop
1. A learner dials a USSD code and registers (name, class/level, optional parent phone number).
2. They pick a subject from a USSD menu.
3. They receive a lesson by SMS.
4. They take a 3-question quiz over USSD.
5. If their score meets a threshold (e.g. 2/3 or better), they get an airtime reward, once per quiz attempt only.
6. After the quiz, one feedback question: "Was this lesson: 1. Easy 2. OK 3. Hard".

## Teacher side (Django admin is enough)
- Upload notes or a PDF for a subject.
- The app generates a short lesson summary and quiz questions from the document using an LLM API, returned as strict JSON. Validate the JSON before saving. If generation fails or the JSON is malformed, fall back to pre-written lessons and questions.
- Send an SMS announcement to a class (timetable changes, deadlines).
- View scores and feedback. Send the teacher an SMS summary after a quiz round (who took it, average score).
- Weekly SMS to a parent with their child's quiz results, if a parent number exists.
- Spaced revision: SMS reminders to re-quiz on a schedule (e.g. day 1, 3, 7).

## Tech stack
- Python 3.10+, Django (plain views or Django REST Framework), SQLite
- Africa's Talking Python SDK (`africastalking`), using the SANDBOX first
- python-dotenv for secrets (.env, never committed)
- pypdf for PDF text extraction
- ngrok to expose local callbacks
- Docker + GitHub at the end

## Architecture rules
- Keep ALL Africa's Talking calls in a `services.py` module (send_sms, send_airtime) so they can be mocked in tests.
- Keep USSD menu logic in a plain function separate from the view, so it can be unit tested without HTTP.
- USSD endpoint receives POST fields `sessionId`, `phoneNumber`, `serviceCode`, `text`. `text` is the full chain of inputs separated by `*` (e.g. `1*2*1`). The response must be plain text starting with `CON ` (continue) or `END ` (finish).
- Models: Learner (phone, name, level, parent_phone), Subject, Lesson, Question, QuizAttempt (score, reward_paid, feedback), Announcement.
- Prevent duplicate airtime rewards with the `reward_paid` flag, checked and set safely.

## Edge cases that must be handled (judges score these)
- Invalid menu input, re-prompting instead of crashing
- Unregistered number dialing in
- USSD session timeout or abandoned quiz, without scoring a partial attempt
- Failed or duplicate airtime sends (try/except, logging, no double pay)
- Malformed LLM output, falling back to pre-written content
- SMS length limits, splitting long lessons into parts
- Phone number formatting (+254...)
